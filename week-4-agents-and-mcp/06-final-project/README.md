# 6. Final Project

**Week 4 - Agents, MCP and shipping · Sat · Hard · about the whole month hours**

## What you will practise

- Everything from the four weeks, in one deployed product
- Judging your own work against a stated bar
- Shipping to a deadline

## Before you start

All four weeks. This is the project you have grown since Week 1, not something new.

## The task

Your final submission is due by **noon on Saturday 28 November**.

**The minimum bar.** Every line must be true, or the project is incomplete:

| # | Requirement |
| --- | --- |
| 1 | A clearly defined user and problem |
| 2 | Week 1 to 3 work still visible in the repository - the data work, the models, the retrieval |
| 3 | An agent with at least three tools, one of them delivered through MCP |
| 4 | Logged traces for agent runs |
| 5 | At least ten test cases with results, and an honest failure analysis |
| 6 | A deployed demo that someone else can open |
| 7 | A README with architecture, results and limitations |
| 8 | A two-minute demo video |
| 9 | A short "How I used AI" note |

**What to submit.** One pull request with the final state, and a description linking the live demo, the video, and the commit you want reviewed.

**How to spend the last week.** Stop building new features after Wednesday. Thursday and Friday are for the README, the evaluation numbers, the video, and fixing what you have been working around all month.

**A warning specific to this track.** Do not delete your Week 1 and 2 work to tidy up. Requirement 2 asks for the progression to be visible: the baseline model, the deep learning comparison, the retrieval evaluation. The journey from a scikit-learn baseline to a deployed agent is the thing being assessed, and a repository holding only the final agent scores worse than one that shows the path.

**Scoring.** Out of 100, pass at 60 with 75 percent attendance, merit at 85. Weekly submissions and quizzes count too - this is the largest single piece, not the only one.

Go through the nine rows yourself before you submit.

## Done when

Tick every line yourself before you submit. If one of them fails, the assignment is not finished.

- [ ] All nine rows of the minimum bar are true, checked one at a time
- [ ] The deployed demo opens for someone who is not you
- [ ] Week 1 to 3 work is still in the repository and findable
- [ ] Three tools work, and one is reachable over MCP
- [ ] Traces exist for agent runs and can be inspected
- [ ] Ten test cases have recorded results and a written failure analysis
- [ ] The README setup steps work on a clean clone
- [ ] The video is under three minutes and shows the real system
- [ ] The pull request description links everything a reviewer needs
- [ ] Submitted before noon on Saturday 28 November

## How we mark it

| What we look at | Exemplary | Adequate | Needs work |
| --- | --- | --- | --- |
| **Completeness** | All nine met, nothing hand-waved | Seven or eight met | Fewer than seven |
| **It actually runs** | Deployed, stable, handles a bad input gracefully | Runs with rough edges | Does not run |
| **Progression visible** | Baseline, deep learning and retrieval all still shown | Partly | Only the final agent |
| **Honesty** | Real numbers and a genuine failure analysis | Partly | Overstated |
| **Presentation** | README and video make it easy to assess | Adequate | Poor |
